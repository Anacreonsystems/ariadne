## Минимальный delta внутри уже утверждённого ADR44

1. **Опциональная версионированная state representation.** Старый INLINE и все v1 request/receipt/graph canonical bytes сохраняются. Для journaled режима seal фиксирует state-owner/codec/representation/size compatibility и child bootstrap переносит эту связь. Точное wire имя/версия пока UNKNOWN. Не добавлять defaulted state field в существующий v1 model_dump без отдельного старого canonical branch: это меняет исторические graph/receipt digests. Неподдержанная representation отвергается до business side effects. NI2-020 остаётся single-input; mailbox/join/NO_OUTPUT относятся к NI2-021…024.
2. **Три необходимые семейства state rows; имена provisional.** State owner/frontier: stable logical owner на graph + original assignment + operator/state-owner/subtask coordinates, accepted apply ordinal/version/root и отдельно derived materialization coordinates. Batch: immutable logical input port/partition/sequence + ordinal, before/after versions/roots, bounded canonical mutation/postimage payload/digest, terminal outcome/route receipt/output linkage. Snapshot: exact owner/cursor frontier, codec/compatibility, content root, completion witness; PREPARED/partial не разрешает restore. TaskRun, grant, physical epoch, generation и holder — audit/fencing поля, не logical accepted-outcome key. Не использовать per-port Consumer или сменяемый TaskRun как единственную будущую shared-state identity. Точные PK/FK/DDL shapes должны быть зафиксированы при реализации; сейчас их нет.
3. **Минимальная batch форма может быть postimage.** ADR44 уже разрешает bounded postimages; user mutation DSL не требуется для первой native интеграции. Но fold обязан проверить каждый ordinal101…200, before→after chain/digests и конечный accepted root. Нельзя пропустить151 и объявить последнюю postimage200 новым complete snapshot. Payload должен использовать существующую strict finite JSON/canonical encoding и `stream_value_JSON` semantics, не обычный JSONB. Existing max_state_bytes default16384/max65536 остаётся frozen bound; batch/snapshot metadata/total retained quota ещё UNKNOWN и должна быть явно ограничена, не заимствуя performance SLO.
4. **Одна acceptance transaction.** Extend только journaled branch _commit_route: после существующего current TaskRun fence сериализовать собственный state owner, затем сохранить прежний sorted partition/Consumer order; accepted lookup раньше выделения следующего ordinal. Batch + accepted frontier + existing route receipt/payload/references/completion/cursor коммитятся вместе. Exact replay не создаёт batch/ordinal/output и не двигает cursor. Не усиливать parent SHARE до UPDATE и не вводить late lock upgrade. Snapshot/fold/resolve обязаны соблюдать тот же owner order; точный порядок новых FK locks проверить перед кодом.
5. **Restore и accepted-result resolution — platform operations.** Current scoped child получает verified snapshot+contiguous batches, platform fold строит state без Task.fn и сверяет accepted root/cursor; derived cache не становится authority. Готовность восстановления должна участвовать в bootstrap-ready/current replacement readiness и read guard до business invocation; healthy siblings не требуют повторной global activation. Нужен scoped logical accepted-batch/receipt lookup для нового current owner без исходного private capability или повторного вычисления старого business output. Existing route receipt используется как исходная immutable output authority, не создаётся второй receipt engine. Старый owner всё равно fenced; другой owner/subtask/graph не может читать/применять state. Точные read/materialize/publish/resolve endpoint names UNKNOWN; не выдавать произвольный SQL или графовый admin доступ child.
6. **Paired transport.** Server/client DTOs отдельно, sync+async методы в client/orchestration/_streams/client.py; routed storage frozen intent/ACK проверяет новые version/root refs только opt-in branch. Дополнить узкие allowlists `_internal/stream_execution.py:308` и routed_storage._dispatch: никаких arbitrary routes. ctx.managed_state остаётся dict; old RETURN wire/state-only смысл и YIELD(null) не меняются. Версионированная OUTPUT/NO_OUTPUT language — NI2-022, не скрытый delta этого slice. Paired PG/SQLite migrations/schema checks; physical journaled profile остаётся PG17, SQLite отказ до mutation.

## Реальный native acceptance oracle A44-01/02/07

На source-bound SDK/TCP/PG17/реальных ProcessWorkers использовать versioned stateful Task: state `sum += input`, отдельный append-only audit вызовов тела/attempted effects и устойчивые client document IDs. Довести корректным native terminal path до COMPLETE local-owner snapshot100 (sum5050), затем durably accept200 (sum20100). Capture receipt/output/cursor/state roots и audit counter200, остановить B настоящим OS death при удержанных healthy siblings. Оставить только snapshot100 как выбираемый complete snapshot и потребовать materialization trace ровно batch101…200; никаких Python callbacks при fold. Сброс только derived cache, если он мешает доказать fold, допустим отдельной явно помеченной owned test-fixture injection — не Flow/Task state mutation и не production GC. Не удалять online journal1…100 ради теста, пока safe-retention API не реализован.

Новый B с тем же logical TaskRun/current grant получает state20100 и cursor200; до первого business201 audit/output/cursor не меняются. После201 ожидаемый sum20301. Exact accepted logical resolution возвращает прежние batch ID/digest/receipt/output IDs без второго output/state advance/cursor movement; stale old child и cross-owner/cross-graph запросы отклоняются. Отдельные missing/corrupt/incompatible151 variants не допускают business201; precommit200 и lost-ACK200 cuts различают200/201. Нужны sync+async parity, прежние INLINE/RETURN regressions, реальная release/whole-health/PID/session closure и independent Principal repeat. Standalone 9-method probe — только reference oracle, не native evidence.

## Что ещё UNKNOWN перед реализацией

- Exact opt-in wire/version/canonical parsing and mixed-version capability negotiation.
- Stable state-owner PK/lookup mapping and exact new lock/FK order; future multi-port ordinal не приравнивать навсегда к input sequence.
- Snapshot local COMPLETE witness format, publish authority и per-replacement materialization-ready binding. Полный graph barrier cut не внедрять раньше NI2-024.
- Bounded journal/snapshot quotas и cleanup/pin semantics finite slice; continuous online GC/retention остаётся ADR46.
- Concrete read/materialize/publish/resolve DTOs/errors and new native test nodeids: пока не существуют.
- Performance, materialization cost, codec migration policy за пределами first compatible JSON profile: не измерены; неизвестное не считать принятою гарантией.

Новый ADR/повторное approval не требуется для обычной реализации уже одобренного решения; действительное изменение approved contract возвращается на architecture review.
