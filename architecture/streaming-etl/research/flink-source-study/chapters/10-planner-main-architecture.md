## Dynamic filtering: control dependency становится graph structure

Batch physical collector проецирует выбранные dimension fields, а ExecNode создаёт collector с **configured parallelism1**. Default threshold8MB ограничивает payload: при превышении coordinator получает empty event с flag, позволяющим отказаться от filtering. Поэтому описанное table reader поведение runtime coordinator «первое событие побеждает» относится к singleton collector, не к distributed union partial sets. [Physical lowering](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/main/scala/org/apache/flink/table/planner/plan/nodes/physical/batch/BatchPhysicalDynamicFilteringDataCollector.scala#L60-L67), [threshold and singleton](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/main/java/org/apache/flink/table/planner/plan/nodes/exec/batch/BatchExecDynamicFilteringDataCollector.java#L55-L106). Runtime body/assertions атрибутируются [05](05-table-sql-planner-runtime.md).

Fact source первоначально имеет collector input как planning dependency. DynamicFilteringDependencyProcessor копирует source без inputs, чтобы убрать cycle в ExecNode DAG, затем вставляет broadcast/BATCH exchange collector→enforcer и source→enforcer вторым input. Все прежние consumers переключаются на enforcer. При mode отличном от ALL_EXCHANGES_BLOCKING processor также требует blocking boundaries на выходах dimension-side upstream closure. Это явная зависимость исполнения, выраженная topology и exchange mode; она не переносит filter rows в обычный fact record stream. [Rewrite](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/main/java/org/apache/flink/table/planner/plan/nodes/exec/processor/DynamicFilteringDependencyProcessor.java#L91-L139), [blocking boundaries](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/main/java/org/apache/flink/table/planner/plan/nodes/exec/processor/DynamicFilteringDependencyProcessor.java#L145-L246).

Во время translation enforcer связывает SourceTransformation.coordinatorListeningID с UUID scan и регистрирует тот же ID у collector factory. Его parallelism берётся у fact source. Ordinary generated operator игнорирует dependent input и collect-ит только второй; fusion spec делает то же и передаёт downstream endInput только от source. Javadoc enforcer требует chaining с source и прямо предупреждает, что disable chaining нарушает ожидаемую работу. Здесь нет persisted signal mailbox/checkpoint protocol: listeners и batch execution order — служебный механизм pruning. ## Compiled source spec: восстановление конфигурации не равно восстановлению данных

DynamicTableSourceSpec хранит resolved table и последовательность SourceAbilitySpec. При первом запросе он выбирает module factory, затем catalog factory fallback, создаёт connector с classloader/context и применяет abilities в сохранённом порядке. После каждой ability, меняющей producedType, следующий context получает новый RowType. Уже установленный через `setTableSource` instance этот replay обходит. Catalog options перечитываются отдельно только для permanent table при restore mode ALL; ALL_ENFORCED не запрашивает catalog, IDENTIFIER уже приходит с catalog table. Это восстановление описания connector/плана; position/split/operator state восстанавливаются другими протоколами из03/06. [Lazy creation and ordered replay](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/main/java/org/apache/flink/table/planner/plan/nodes/exec/spec/DynamicTableSourceSpec.java#L72-L119), [catalog policy](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/main/java/org/apache/flink/table/planner/plan/nodes/exec/spec/DynamicTableSpecBase.java#L33-L51).

Projection сохраняет nested index paths и produced type; metadata-reading сохраняет ordered keys. Обычные фильтры на restore заново преобразуются RexNode→ResolvedExpression и должны все попасть в accepted list (проверяется её размер). Metadata filters используют отдельный сохранённый predicateRowType с metadata key names, поэтому последующая projection не меняет их namespace; replay требует identity именно переданных ResolvedExpression instances и покрытия каждого input. Поле `allPredicatesRetained` ordinary filter относится только к optimization phase и не сериализуется. Accepted-predicate replay подтверждает согласие connector с прежней оптимизацией; реальное чтение/фильтрация остаётся контрактом connector, а residual operator определяется optimization rule. [Ordinary filter replay](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/main/java/org/apache/flink/table/planner/plan/abilities/source/FilterPushDownSpec.java#L67-L116), [metadata namespace and identity](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/main/java/org/apache/flink/table/planner/plan/abilities/source/MetadataFilterPushDownSpec.java#L66-L112).

Watermark ability сохраняет expression/optional rowtime expression и параметры, генерирует supplier, добавляет alignment/idleness и передаёт strategy connector. Source-specific idle timeout ≥0 перекрывает global; значение0 отключает добавление idleness. Это recipe нового generator, не сохранённая текущая watermark. StreamExecTableSourceScan versions1/2 также меняют metadata UID filling для custom providers; compiled node version имеет поведенческий смысл. [Strategy construction](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/main/java/org/apache/flink/table/planner/plan/abilities/source/WatermarkPushDownSpec.java#L93-L128), [timeout precedence](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/main/java/org/apache/flink/table/planner/plan/abilities/source/WatermarkPushDownSpec.java#L202-L207), [node versions](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/main/java/org/apache/flink/table/planner/plan/nodes/exec/stream/StreamExecTableSourceScan.java#L45-L59).

## Catalog object → relational table → source semantics

Root Calcite schema отображает CatalogManager как catalog/database/object. Schema snapshot копирует FlinkSchema wrapper и сохраняет SchemaVersion; DatabaseCalciteSchema поддерживает только TimestampSchemaVersion и передаёт timestamp в catalog table lookup. Это versioned metadata lookup, не snapshot текущего runtime state. Table/column statistics загружаются отдельно обычными catalog methods, temporary table получает UNKNOWN; нельзя приравнивать слово snapshot здесь к атомарному срезу данных и статистики. [Schema wrapper snapshot](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/main/java/org/apache/flink/table/planner/catalog/FlinkSchema.java#L64-L75), [version and stats lookup](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/main/java/org/apache/flink/table/planner/catalog/DatabaseCalciteSchema.java#L78-L142).

FlinkCalciteCatalogReader превращает CatalogSchemaTable во временный preparing wrapper: QueryOperation view lowering, SQL view expansion, legacy connector либо modern catalog source. SQL view повторно expands expanded query и cast-ит к объявленному row type; QueryOperation view идёт через relBuilder, также с final cast. Legacy detection может вызвать factory с удалёнными time indicators и при Throwable перейти на modern path; CatalogSchemaTable.getRowType имеет отдельный compatibility probe, ловящий Exception. Эти construction callbacks выполняются при planning, поэтому schema/type inspection не следует считать чистым чтением immutable descriptor без connector factory calls. [Preparing dispatch](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/main/java/org/apache/flink/table/planner/plan/FlinkCalciteCatalogReader.java#L140-L177), [legacy probe](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/main/java/org/apache/flink/table/planner/plan/FlinkCalciteCatalogReader.java#L245-L291), [view expansion](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/main/java/org/apache/flink/table/planner/catalog/SqlCatalogViewTable.java#L55-L60).

Modern CatalogSourceTable сначала применяет allowed OPTIONS hints, создаёт source и вызывает DynamicSourceUtils: metadata capability/type validation и apply → logical scan с physical+metadata columns → metadata reorder/casts → computed-column projection → streaming watermark assigner. Metadata порядок задаёт connector readable-metadata map, SQL aliases возвращает projection. Computed expressions получают уже cast metadata. Batch требует bounded provider и insert-only changelog; streaming UA без UB требует PK, UB без UA отвергается, CDC duplicate normalization config также требует PK. DELETE не допускает IMMUTABLE constraint. [Lowering sequence](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/main/java/org/apache/flink/table/planner/connectors/DynamicSourceUtils.java#L115-L158), [projection](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/main/java/org/apache/flink/table/planner/connectors/DynamicSourceUtils.java#L319-L378), [changelog/boundedness admission](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/main/java/org/apache/flink/table/planner/connectors/DynamicSourceUtils.java#L524-L595).

Construction identity также зависит от entry point: первоначальный CatalogSourceTable даёт catalog factory precedence над module, тогда как lazy DynamicTableSourceSpec restore выбирает module первым и лишь затем catalog. Model provider выбирает catalog первым. Это три конкретных selection contracts, а не одна универсальная precedence. TableSourceTable включает ability digests в qualified name, последовательно меняя produced type; copy заменяет все specs того же concrete class новыми в конце списка.
