# Planner tests: проверки, fixtures и границы доказательства

Исследуемая ревизия: `068f428b29f4d9ee587fa1006d2f1a69b43c0000`. После закрытия исходного execution-раздела эта глава охватывает оставшийся текст `flink-table-planner/src/test/java` и `src/test/scala`: исходная передача содержит 861 файл и 265134 строки. Owner inventory остаётся table; личные подтверждения добавляются в [execution.confirmed.jsonl](../readers/execution.confirmed.jsonl), общее покрытие объединяет диапазоны всех читателей. Корпус ещё не прочитан целиком. Тесты, builds, генерация golden files и MiniCluster здесь не запускались: ниже описаны прочитанные assertions и устройство их среды.

## Built-in aggregate test base

BuiltInAggregateFunctionTestBase объявляет MiniClusterExtension и параметризованные TestCase. Каждый TestItem разворачивается в отдельный streaming TableEnvironment для hashmap и rocksdb; тестовый source выводит insert-only changelog только если все входные RowKind — INSERT, иначе объявляет all. Ограниченный DataGeneratorSource выдаёт ровно rows.size записей с conversion в RowData. Это среда семантического запуска, заложенная в тесте, а не выполненный запуск в исследовании ([test/source](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/table/planner/functions/BuiltInAggregateFunctionTestBase.java#L88-L153), [backend cases](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/table/planner/functions/BuiltInAggregateFunctionTestBase.java#L353-L391)).

SuccessItem проверяет children итогового row DataType и материализованный результат без учёта порядка. Materializer нормализует INSERT/UPDATE_AFTER в INSERT и добавляет строку, UPDATE_BEFORE/DELETE нормализует и удаляет первое равное вхождение из списка; неуспешный remove не проверяется. Следовательно equality итогового multiset не удостоверяет полный порядок changelog или наличие каждого соответствующего retract. SQL, Table API и API→serialized SQL имеют отдельные пути; последний пересобирает select/grouping из query operations, а не восстанавливает runtime checkpoint ([materialization](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/table/planner/functions/BuiltInAggregateFunctionTestBase.java#L156-L179), [assertions](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/table/planner/functions/BuiltInAggregateFunctionTestBase.java#L418-L490), [API as SQL](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/table/planner/functions/BuiltInAggregateFunctionTestBase.java#L510-L584)).

ErrorTestItem различает исключение при query.execute и runtime failure после успешной validation. Runtime path вызывает TableResult.await, затем requestJobResult и извлекает SerializedThrowable; assertions ищут заданную cause/message. Такие тесты проверяют соответствующий failure path и тип результата; сами по себе не доказывают recoverability, exactly-once external effects или checkpoint restoration ([error matching](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/table/planner/functions/BuiltInAggregateFunctionTestBase.java#L604-L678)).

## Прямые accumulator-тесты retract aggregates

AggFunctionTestBase вызывает методы AggregateFunction через reflection без TableEnvironment, operator, mailbox и state backend. Он проверяет accumulate/getValue, полный retract обратно к freshly created accumulator, merge двух половин, merge с пустым accumulator и reset. Equality accumulator опирается на equals самой реализации; сравнение не является независимой проверкой каждого поля. Отдельный testMergeReservedAccumulator создаёт отрицательный accumulator через retract всего input в пустой, затем сливает positive и negative в новый accumulator и добавляет net-zero результат к заранее сохранённому subset. Это реальная заложенная проверка компенсации отрицательных counts, но не сценарий с одновременно остающимися положительными и отрицательными ключами при пересчёте extrema ([direct paths](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/table/planner/functions/aggfunctions/AggFunctionTestBase.java#L62-L147), [reverse merge](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/table/planner/functions/aggfunctions/AggFunctionTestBase.java#L150-L193), [reset/equality](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/table/planner/functions/aggfunctions/AggFunctionTestBase.java#L196-L222)).

MaxWithRetractAggFunctionTest и MinWithRetractAggFunctionTest задают типовые матрицы boolean, целочисленных, floating, decimal, string, date/time и timestamp с precision 3/9. Numeric extrema в fixtures находятся внутри диапазона, integer min+1/max−1 и floating ±MAX/2; null-only и null+value ожидают null/значение. Их собственные тела не содержат TTL, восстановления state или targeted signed-debt scan assertions: они наследуют перечисленные direct accumulator-проверки. Это дополнение к runtime implementation evidence главы 05, не подтверждение корректности произвольного changelog ([max typed fixture](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/table/planner/functions/aggfunctions/MaxWithRetractAggFunctionTest.java#L60-L214), [max inherited matrix](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/table/planner/functions/aggfunctions/MaxWithRetractAggFunctionTest.java#L512-L574), [min inherited matrix](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/table/planner/functions/aggfunctions/MinWithRetractAggFunctionTest.java#L508-L570)).

LISTAGG fixture ожидает порядок a,b,c,d,e,f при null-пропусках и наследует те же retract/merge checks. LISTAGG_WS хранит тестовые параметры парами value/delimiter и сдвигает split point к чётному индексу, чтобы merge не разрывал пару. Матрица отличает null value с newline delimiter от последнего nonnull c с comma либо newline: ожидаются a,b,c либо a\nb\nc. Проверки меняющегося результата через delimiter существуют; отдельного сравнения accumulator equality при разных delimiter эти test files не задают ([LISTAGG](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/table/planner/functions/aggfunctions/ListAggWithRetractAggFunctionTest.java#L34-L69), [delimiter cases](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/table/planner/functions/aggfunctions/ListAggWsWithRetractAggFunctionTest.java#L74-L102), [pair boundaries](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/table/planner/functions/aggfunctions/ListAggWsWithRetractAggFunctionTest.java#L129-L168)).

FIRST_VALUE/LAST_VALUE с явным order используют отдельный paired-input base: размеры value/order проверяются, accumulate и retract вызываются с одной и той же парой, после полного retract accumulator сравнивается с новым; reset проверяется отдельно. Typed fixtures содержат произвольный порядок поступления, null и повторяющиеся order. Numeric LAST_VALUE ожидает значение 3 с order 13, хотя последняя запись имеет order 5; без order те же семейства ожидают первый либо последний nonnull по последовательности вызовов. ARRAY_AGG direct fixture создаёт функцию с ignoreNulls=true для всех типов, включая row и array: верхнеуровневые null исключены, вложенные null полей/элементов сохранены. ## Filesystem и source fixtures

FileSystemStatisticsReportTest проверяет статистику optimized plan, а не фактическое число выданных записей. Полные catalog statistics имеют приоритет над source estimate; отсутствие статистики хотя бы одной partition приводит к пересчёту по source. FileSystemTableSinkTest сравнивает JSON explain с golden после нормализации node/stage IDs для parallelism и compaction; отдельный тест действительно задаёт INSERT и await, затем сравнивает набор paths custom policy. Streaming source test собирает первые строки, публикует следующий файл и собирает ещё строки; публикация сделана через временный файл и ATOMIC_MOVE, чтобы monitor не видел неполный файл. Сценария failure/restore здесь нет ([sink oracles](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/connector/file/table/FileSystemTableSinkTest.java#L64-L121), [custom policy test](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/connector/file/table/FileSystemTableSinkTest.java#L160-L194), [set oracle](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/connector/file/table/TestCustomCommitPolicy.java#L45-L56), [monitor](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/connector/file/table/FileSystemTableSourceStreamingITCase.java#L47-L89), [atomic publication](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/connector/file/table/FileSystemTableSourceStreamingITCase.java#L151-L158)).

ValuesSource хранит сериализованные RowData в source, выдаёт по одному split на индекс и отличает declared boundedness от FINITE/INFINITE поведения после данных. QueryOperationSqlSerializationTest проверяет точное asSerializableString и отдельно job name StreamGraph после translate. ## Validation и catalog metadata

MatchRecognizeValidationTest параметризован stream/batch; часть методов выполняет assertions только в STREAM branch. Там заложены запреты descending primary time, отсутствующего time order и upstream update changes. Общие проверки отвергают aggregate по нескольким pattern variables, ambiguous measure names, Python function, ALL ROWS PER MATCH, greedy terminal quantifier, empty-match pattern и DISTINCT aggregate. Это проверка отклонённых запросов на указанной ревизии, без runtime NFA semantics ([mode/setup](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/table/api/batch/sql/validation/MatchRecognizeValidationTest.java#L44-L86), [stream restrictions](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/table/api/batch/sql/validation/MatchRecognizeValidationTest.java#L111-L192), [unsupported patterns](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/table/api/batch/sql/validation/MatchRecognizeValidationTest.java#L271-L373)). FlinkCalciteSqlValidatorTest отдельно отклоняет ARRAY_AGG с ORDER BY и JSON_ARRAYAGG с ORDER BY/WITHIN GROUP, но принимает неупорядоченные формы; partial INSERT field lists и mixed positional/named function arguments проверяются отдельно ([aggregate order validation](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/table/planner/calcite/FlinkCalciteSqlValidatorTest.java#L146-L212)).

CatalogConstraintTest проверяет вывод unique keys, immutable columns и upsert keys из schema metadata; immutable constraint с DELETE changelog отклоняется. Существенный оракул — первая совпавшая ветвь сохраняет результат, а позднее условие с делением на ноль не вычисляется; отдельно проверены nullable condition и null-result в позднем фрагменте. Это семантика вычисления выражения, без утверждения о checkpoint или восстановлении ([границы](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/table/planner/functions/CaseFunctionsITCase.java#L114-L176)).

## 14. CAST: тип источника меняет границу ошибки

В `CastFunctionITCase` обычное narrowing чисел ожидает wrapping/truncation: DECIMAL 9123.87 → TINYINT −93 и BIGINT 12345678901 → INT −539222987. Это нельзя переносить на VARIANT: там тесты ожидают ошибку при overflow или потере дробной точности, а `TRY_CAST` возвращает null. Для VARIANT-array fractional leaf обнуляет весь ARRAY при TRY_CAST, а не только проблемный элемент. ROW выбирает поля по имени, лишние отбрасывает, отсутствующее поле считает ошибкой; nullable JSON null отличается от отсутствующего поля ([обычные числа](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/table/planner/functions/CastFunctionITCase.java#L1458-L1608), [VARIANT precision](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/table/planner/functions/CastFunctionITCase.java#L219-L266), [вложенный отказ](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/table/planner/functions/CastFunctionITCase.java#L945-L986), [ROW projection](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/table/planner/functions/CastFunctionITCase.java#L1086-L1128)).

Обычные ROW/ARRAY/MAP также имеют сценарии TRY_CAST, где ошибка внутри контейнера даёт null всему результату; invalid UTF-8 bytes → STRING даёт null. RAW→bytes проверяется на конкретных байтах пользовательских функций, поэтому это не универсальный JSON/wire-format. В legacy-cast сценарии invalid STRING→BIGINT сначала даёт null, а наблюдаемая ошибка относится уже к NOT NULL sink enforcer ([контейнеры и UTF-8](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/table/planner/functions/CastFunctionMiscITCase.java#L295-L364), [legacy](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/table/planner/functions/CastFunctionMiscLegacyITCase.java#L36-L59)).

Раздел `numericBounds` требует осторожного чтения: выражения `(byte)(Byte.MAX_VALUE + 1)` и `Integer.MAX_VALUE + 1` уже переполнены Java до передачи в Flink; эти строки подтверждают обработку полученного значения, а не проверку исходной математической величины во Flink. Builder дополнительно проверяет `supportsExplicitCast`, но название helper не заменяет тело: `failSqlValidation` в этом файле направляет в `ERROR_TABLE_API`; обычный `failValidation` отдельно добавляет оба маршрута. Здесь зафиксировано устройство оракула, без заявления о результате запуска ([входные bounds](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/table/planner/functions/CastFunctionITCase.java#L2421-L2447), [builder](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/table/planner/functions/CastFunctionITCase.java#L2584-L2608)).

## 15. Коллекции: null, равенство и предел сортировочного оракула

`CollectionFunctionsITCase` различает null-массив и null-элемент: ARRAY_CONTAINS ищет null как значение, ARRAY_REMOVE удаляет его, ARRAY_DISTINCT/UNION/EXCEPT/INTERSECT имеют проверки дубликатов и вложенного ROW/MAP/ARRAY, тогда как CONCAT сохраняет повторения. ARRAY_POSITION возвращает позицию с единицы либо 0 для отсутствующего значения; поиск NULL отдельно ожидает null. Эти функции нельзя описывать одной общей политикой null ([contains](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/table/planner/functions/CollectionFunctionsITCase.java#L127-L191), [position](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/table/planner/functions/CollectionFunctionsITCase.java#L284-L317)).

ARRAY_SORT действительно имеет дубликаты: вход `[1,2,2,null]` и ожидаемые результаты для ascending/descending и nulls-first/last. Остальные успешные наборы — шесть разных DOUBLE, STRING и DATE; ROW отвергается при validation. Здесь нет прямых проверок `compare(x,x)==0`, антисимметрии, случайных длинных массивов либо массива полностью одинаковых значений. Поэтому эти expected arrays не закрывают замечание о контракте comparator, разобранное по runtime-коду в главе 05 ([весь sort-сценарий](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/table/planner/functions/CollectionFunctionsITCase.java#L1460-L1602)).

COALESCE проверяет runtime-laziness с UDF, всегда бросающей исключение: ненулевой первый или средний аргумент должен её пропустить, а отдельный negative control с null-предшественником обязан дойти до UDF и получить ошибку. Это сильнее проверки одного правильного значения, но остаётся оракулом для конкретного выражения и указанных типов ([positive и negative controls](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/table/planner/functions/CoalesceFunctionITCase.java#L278-L319)).

Доступ к вложенному ROW и lookup в ARRAY/MAP имеют разные type-oracles: nullable parent ROW делает поле nullable даже при объявленном внутреннем NOT NULL; при non-null parent внутренний NOT NULL сохраняется. Для ARRAY/MAP lookup результат nullable даже при non-null контейнере и элементах, поскольку наличие позиции/ключа определяется при исполнении. `ConstructedAccessFunctionsITCase` дополнительно ожидает validation error при передаче такого nullable поля в primitive-аргумент UDF и проверяет, что `TableFunction.collect(null)` не добавляет строку в соответствующий результат ([доступ к полям](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/table/planner/functions/FieldAccessFromTableITCase.java#L44-L87), [primitive UDF и null-row](https://github.com/apache/flink/blob/068f428b29f4d9ee587fa1006d2f1a69b43c0000/flink-table/flink-table-planner/src/test/java/org/apache/flink/table/planner/functions/ConstructedAccessFunctionsITCase.java#L62-L109)).
